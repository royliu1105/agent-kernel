# Agent Kernel v0.1

Agent Kernel v0.1.0 is the first published release of the project.

It is a self-hosted, observable, evaluable, resumable AI Agent runtime
foundation with API, CLI, worker, Web Workbench, tools, approvals, RAG, memory,
observability, evals, Docker Compose, docs, and examples.

v0.1 is not a toy demo. It is also not yet a final production SaaS platform.

## Positioning

One-sentence positioning:

```text
Agent Kernel is a production-grade foundation for building, inspecting, and evaluating AI agent runtimes.
```

The v0.1 goal is:

```text
A developer can clone the repository, run the core runtime locally, inspect behavior, run evals, open the Workbench, and understand what is implemented or deferred.
```

## What v0.1 Is

v0.1 is:

- A modular monorepo.
- A Python backend runtime.
- A TypeScript/Next.js Workbench surface.
- A CLI-first local developer workflow.
- A worker-based execution model.
- A persisted run lifecycle foundation.
- A tool execution and human approval foundation.
- A RAG and memory foundation.
- An observability and eval foundation.
- A published foundation for further Public Alpha hardening.

## What v0.1 Is Not

v0.1 is not:

- A public multi-tenant SaaS.
- A managed cloud platform.
- A complete no-code agent builder.
- A chat-only demo.
- A fully live Web operations console.
- A production identity, authorization, and tenant-isolation system.
- A complete replacement for deployment, secret, and network controls.

## Current Product Shape

Backend workflow:

```text
create agent -> create run -> queue run -> worker executes -> inspect output and timeline
```

Tool and approval workflow:

```text
explicit tool request -> policy decision -> safe execution or approval pause -> approve/reject -> resume or fail safely
```

RAG workflow:

```text
create KB -> upload document -> ingest -> chunk -> index -> retrieve -> cited kb_search result
```

Memory workflow:

```text
create scoped memory -> list/inspect/delete -> explicit memory context injection
```

Eval workflow:

```text
JSON dataset -> deterministic eval runner -> JSON report -> CI cheap eval
```

Workbench workflow:

```text
Dashboard -> Agents -> Runs -> Approvals -> Knowledge -> Evals -> Settings
```

## CLI Overview

v0.1 includes CLI commands for:

- Creating agents.
- Creating, queueing, inspecting, canceling, and listing run events.
- Listing, inspecting, approving, and rejecting approvals.
- Creating and inspecting knowledge bases.
- Uploading, ingesting, chunking, indexing, and searching documents.
- Creating, listing, inspecting, and deleting memory.
- Running deterministic eval reports.

JSON object options support both inline JSON and file input:

```bash
--input '{"task":"hello","model":"mock:echo"}'
--input @examples/mock-run.json
```

## Worker Overview

The v0.1 worker executes persisted queued runs:

```bash
agent-kernel-worker --once --limit 10
agent-kernel-worker --loop --limit 25 --poll-interval 2
```

Redis-backed durable queue scheduling and distributed leases are deferred.

## Production Readiness

v0.1 is production-grade as a runtime foundation, but not production-complete as
a public hosted platform.

Reasonable v0.1 use:

- Local agent runtime learning.
- Internal prototype foundation.
- Runtime architecture reference.
- Deterministic eval experimentation.
- RAG/memory/tool/approval workflow exploration.
- Basis for Public Alpha hardening.

Do not use v0.1 as a public multi-tenant deployment without adding:

- Authentication.
- Authorization.
- Tenant isolation.
- Secret management.
- Network hardening.
- Live Web API integration.
- Operational telemetry exporters.
- Deployment-specific backup and recovery.
