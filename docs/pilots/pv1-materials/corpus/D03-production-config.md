# D03: production-config

本地脱敏摘要草案；待人工审核，未授权外发或导入知识库。
仅描述版本化文档约定，不证明当前 Docker 已部署该版本。

## D03-S1: 执行位置

API、Worker 是独立进程。新建并排队的 Run 由 Worker 执行；POST /v1/runs/{id}/resume 当前在 API 中同步执行一个有界续跑片段，到结束、失败或下一次审批时返回，并不是后台排队续跑。代理和客户端超时应大于有效执行时间上限。传输超时不证明执行失败，应先查询 Run 和工具状态。

## D03-S2: 向量配置

mock 适合确定性开发与回归，不证明真实语义检索质量。索引、查询以及 API/Worker 的 kb_search 必须使用一致的 Embedding provider、model 和 dimensions。DeepSeek 生成与 DashScope 向量使用独立凭据；该试点配置使用 text-embedding-v3、1024 维，默认环境仍是 mock。已有向量不会因配置修改而自动转换；切换后须在获准的受控环境重新生成受影响文档的向量并完成索引，再以新配置查询。这不同于只重建数据库 HNSW 索引。

## D03-S3: 性能与费用

原有 pgvector 表达式 HNSW 索引针对 1536 维；其他维度的正确查询不等于性能已验收。需要匹配的索引策略及测量后才能声称性能就绪。真实模型、向量、重试会产生潜在费用，凭据存在不等于调用授权。

## D03-S4: 重试与凭据

合格的瞬时失败使用有界指数退避、抖动和安全 Retry-After；已审批工具和写工具不自动重试。生产凭据由平台秘密管理机制注入，不提交到仓库。
