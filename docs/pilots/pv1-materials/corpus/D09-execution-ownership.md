# D09: execution-ownership

本地脱敏摘要草案；待人工审核，未授权外发或导入知识库。
仅描述版本化文档约定，不证明当前 Docker 已部署该版本。

## D09-S1: 租约与 fencing

execute 和 resume 都取得数据库租约，所有状态、usage、工具结果与审计写入要求当前未过期 token。丢失所有权或取消后禁止迟到结果覆盖状态。这样可避免旧执行器在新所有者运行时仍写入；它不能撤销远端已经接受的请求。

## D09-S2: 决策不等于执行

审批决策只记录审核结果。要执行受保护工具，需要之后的 resume 获取租约、验证持久化参数并继续。重复相同决策不新增审核事件，相反决策冲突。新执行器可使用私有 checkpoint 继续原批次，不重放已完成工具。

## D09-S3: 核对实际效果

证明一次执行需同时核对工具记录、Run 事件和下游独立调用次数，而不能只看 approved 或 HTTP 200。使用稳定持久化 tool_call_id 作为下游幂等上下文，不能使用租约 token。发生超时、进程死亡或不确定远端效果时先对账，不盲目重试。数据库 fencing 不保证全局 exactly-once。

## D09-S4: 恢复与局限

过期 running/resuming 工作由显式恢复标记失败以待审查，不自动重排可能有副作用的任务；queued 工作保留。取消不强制终止任意 Python 代码或远端副作用。Run 彼此独立，没有跨 Run 会话顺序保证。
